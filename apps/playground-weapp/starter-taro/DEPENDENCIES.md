# Taro dependency and compiler boundary

Direct dependencies are pinned. The exporter prepares source, a new pnpm 11.24.0 lockfile, and provenance records in a temporary sibling directory. Install the result separately with `--frozen-lockfile`. `autoInstallPeers: false` and `strictPeerDependencies: true` require explicit peers; unrelated optional frameworks are not installed. Audit, integrity, and security checks remain enabled.

## Observed upstream contracts

The following versions and constraints were checked against the npm registry (`pnpm view`) and published packages on 2026-10-06:

- **Taro 4.3.0** is the observed stable release. All direct Taro compiler/runtime/platform packages use this exact version. [Official default package template](https://unpkg.com/@tarojs/cli@4.3.0/templates/default/package.json.tmpl), [Vue 3 guide](https://docs.taro.zone/docs/vue3), [composition lifecycle APIs](https://docs.taro.zone/docs/composition-api), [configuration](https://docs.taro.zone/docs/config-detail).
- **Vue 3.5.43**, matching compiler-sfc/runtime-core, satisfies the framework plugin's Vue `^3` peer. **vue-loader 17.4.2** satisfies `^17`; **vue-tsc 3.3.12** accepts TypeScript `>=5.0.0`, with the existing **TypeScript 5.9.3** line pinned. [Vue framework plugin metadata](https://unpkg.com/@tarojs/plugin-framework-vue3@4.3.0/package.json).
- **webpack 5.111.1** remains the compatible webpack 5 compiler pin. Taro's Vue plugin accepts `^5`, but its **webpack5-runner**, **taro-loader**, and **webpack5-prebundle**, each at **4.3.0**, publish the older exact peer `5.91.0`. The three `peerDependencyRules.allowedVersions` entries admit **only 5.111.1 for these exact three upstream versions**. This explicit same-major compiler substitution keeps peer ownership bounded and does not claim upstream certification. Both real compiler targets must be exercised for this combination. [Runner metadata](https://unpkg.com/@tarojs/webpack5-runner@4.3.0/package.json), [loader metadata](https://unpkg.com/@tarojs/taro-loader@4.3.0/package.json), [prebundle metadata](https://unpkg.com/@tarojs/webpack5-prebundle@4.3.0/package.json), [pnpm scoped peer policy](https://pnpm.io/settings/peer-dependencies#peerdependencyrulesallowedversions).
- **Babel core/runtime 7.29.7** retain the supported Babel 7 compiler family rather than adopting the current Babel 8 major; **babel-preset-taro 4.3.0** and **@vue/babel-plugin-jsx 1.5.0** follow the Vue peer path. Other JSX/framework preset peers are optional. [Babel preset metadata](https://unpkg.com/babel-preset-taro@4.3.0/package.json).
- **weapp-tailwindcss 5.5.11**, **Tailwind CSS 4.3.3**, **@weapp-tailwindcss/merge 2.2.6**, and **PostCSS 8.5.29** are observed published versions. The upstream integration registers `WeappTailwindcss` for both H5 and native builds, takes over Tailwind generation, and requires an explicit CSS entry. `src/styles.css` is that entry. [Primary Taro integration documentation](https://tw.weapp.dev/docs/quick-start/frameworks/taro).
- The strict fresh lock resolver exposed non-optional peers shipped by Taro's broad platform/tooling packages, even for a Vue app: `@tarojs/plugin-platform-h5` depends on `@tarojs/components-react`, which requires React and Solid; its map dependency requires React DOM. **React/React DOM 18.3.1** and **Solid 1.9.15** are explicit development peers, not a second application renderer. Taro's included loader chain also requires **Less 4.9.1** and **Stylus 0.64.0**, although the retail source uses plain CSS. These peers are declared rather than hidden with `ignoreMissing`. [H5 plugin metadata](https://unpkg.com/@tarojs/plugin-platform-h5@4.3.0/package.json), [component package metadata](https://unpkg.com/@tarojs/components-react@4.3.0/package.json).
- **schema-utils 4.7.0** is the compatible validation dependency for this compiler family. Fresh resolution on 2026-10-20 selected 4.8.1, whose webpack `^5.112.0` peer rejected the fixed compiler. Although webpack 5.112.0 passed H5 compilation, it moved `lib/dependencies/EntryDependency` to `lib/entry/EntryDependency`, breaking Taro 4.3.0's native compiler import. The bounded `schema-utils@^4` override selects published 4.7.0 for the declared 4.x dependency ranges, including webpack 5.111.1's `^4.5.0`; this validator has no webpack peer. Older schema-utils major lines stay unchanged; strict peer checks remain enabled. [Validator metadata](https://unpkg.com/schema-utils@4.7.0/package.json), [webpack dependency metadata](https://unpkg.com/webpack@5.111.1/package.json).

## Why not Taro Vite

[Taro vite-runner 4.3.0](https://unpkg.com/@tarojs/vite-runner@4.3.0/package.json) requires Vite ^4, which is outside the [Vite maintenance policy](https://vite.dev/releases). The weapp-tailwindcss guide also recommends Webpack for new Taro projects because of Vite stability and style issues. This starter uses Webpack without a second compiler, incompatible Vite upgrade, or undocumented runtime patch.

## Runtime, tooling and install effects

Application source uses Vue, Taro APIs/components, `clsx`, class merging, and copied Varo helpers. H5 and WeChat each use Taro's platform runtime. Wevu, weapp-vite, uni-app, workspace aliases, and compatibility runtimes are not included.

The exported native verifier includes the shared `scripts/css-references.mjs` helper and pins the MIT-licensed `@csstools/css-tokenizer` 4.0.2 as a development dependency. It resolves CSS escapes in stylesheet imports and asset URLs before checking their real files, preserving query/hash suffix semantics and leaving external URLs outside filesystem checks.

`allowBuilds` permits only the native bindings used by the compiler/Tailwind chain (`@parcel/watcher`, `@swc/core`, `@tailwindcss/oxide`, `esbuild`). **Taro CLI postinstall is explicitly declined**: upstream 4.3.0 contacts `taro.jd.com` and tries to globally install an unpinned build-performance reporting plugin via an HTTP registry. That is not needed for this exported app and is not authorized by installation. Taro binding's optional source-build postinstall is also declined; pnpm installs its platform-specific prebuilt binary package instead. Core-js donation notices are declined. No dependency patch edits compiled retail artifacts. [CLI postinstall source](https://unpkg.com/@tarojs/cli@4.3.0/postinstall.js), [binding postinstall source](https://unpkg.com/@tarojs/binding@4.3.0/postinstall.js).

Audit the exported lockfile with `pnpm audit --json` and distinguish application dependencies from development tools. Taro's transitive dependencies may retain advisories even with current direct packages. Local binding and build success do not resolve them: keep dev servers off untrusted networks and do not compile untrusted source. Review compatibility before replacing transitive packages across major versions.

Taro's `webpackbar` 5.0.2 puts display settings in webpack's `ProgressPlugin.options`, where webpack 5.111.1 rejects them. Both target configurations use webpack's public `ProgressPlugin` instead. Diagnostics, build stats, exit status, and schema validation remain unchanged. No external `callReporters` caller uses the removed subclass in the runner/Vue plugin dependencies; no webpack downgrade or webpackbar major override is needed.

## Bounded security fixes and residual audit findings

The first real lock audit reported upstream exact-pinned lodash/lodash-es 4.17.21. Three exact Taro 4.3.0 dependency edges now use the published same-major **4.18.1**, addressing [template-injection](https://github.com/advisories/GHSA-r5fr-rjxr-66jc) and [prototype-pollution](https://github.com/advisories/GHSA-f23m-r3pf-42rh) advisories without replacing an unrelated dependency major.

The required alternative-framework peer `solid-js` 1.9.15 pins `seroval` to `~1.5.4`; the observed 1.5.6 has [GHSA-p6vx-979v-rg4c](https://github.com/advisories/GHSA-p6vx-979v-rg4c). A fourth exact-owner override selects the published same-major **seroval 1.6.1**. `seroval-plugins` 1.5.4 accepts `seroval ^1.0`. This does not change the starter's Vue renderer or add a serialization feature.

Taro 4.3.0 components import **`swiper/bundle`**, pinned upstream to Swiper **11.1.15**. That entry imports `shared/swiper-core.mjs`, which imports `shared/utils.mjs`. The version-pinned pnpm patch backports the exact key-filter change from [upstream commit d3e6633](https://github.com/nolimits4web/swiper/commit/d3e663322a13043ca63aaba235d8cf3900e0c8cf) for [GHSA-hmx5-qpq5-p643](https://github.com/advisories/GHSA-hmx5-qpq5-p643): direct comparisons reject `__proto__`, `constructor` and `prototype` even if `Array.prototype.indexOf` is replaced. This does **not** claim to patch standalone pre-minified CDN distributions or every Swiper entrypoint. Do not substitute such files for the package entry used by Taro. The patch and its lockfile hash are included in export provenance; package-version auditing will still flag 11.1.15 despite this local backport.

The audit also found advisories in CLI archive/download helpers, `html-minifier`, older dev-server/esbuild dependencies, simulator PostCSS, and other tools. They remain unsuppressed; the dependency audit is not clean. Review the exported lockfile, avoid untrusted templates and source, and keep the dev server off untrusted networks. Local patches cover only the issues described above.
